## 一、这一版要解决的问题

v0.2.5 让"更新"变得可中断、可继续、装前先验。但**安装这一步自己失败**时，用户仍然只有一条路：
再点一次「立即更新」—— 它会从头重走 `resolve → download → verify → install`，而其中前三步的
成果本来都还有效。

更麻烦的是第二条：失败之后**退无可退**。回退点原本只在更新**成功**后才写进状态：

```js
if (result.ok && result.after !== undefined) {
  rollback.script = writeRollbackScript(rollback, say)   // ← 只有成功才记
}
```

于是"装到一半失败"正好落进缝里：这是最需要退路的时刻（工作区可能已经被动过），
却恰恰没有回退记录 —— `POST /rollback` 只会回一个 409「没有可回退的更新记录」。

v0.2.6 补的就是这两条：**失败可以只重试安装**，**失败也可以回退到更新前**。

## 二、交付内容

### 把"准备"与"安装"拆开

`applyPackageUpdate` 原本一口气做完四件事。现在拆成：

| 步骤 | 产物 |
|---|---|
| `stagePackage`（原 `applyPackageUpdate` 前半段） | 一个**已就绪的包**：`{ version, file, integrity, shasum, checks, bytes, total, resumedFrom }` |
| `installStagedPackage`（新） | 装上去，或在失败时返回失败原因（并把 `staged` 一起带回去） |

拆开的直接收益：安装失败时，"已经下好并校验过的那份字节"还在手里，
不必为了重试再走一遍网络。

### `POST /update/retry`

- **npx / npm 形态**：取状态里暂存的包（内存 → 状态文件，所以**重启后仍可重试**），
  校验安装位置没变，然后只做安装。
- **源码形态**：重试的是"快进合并"这一步 —— 用 `git rev-parse --verify FETCH_HEAD` 确认
  上次抓取的结果还在，在就直接 `merge --ff-only FETCH_HEAD`，**不再走网络**。
- 没有可重试的记录时返回 409；安装位置变化（换形态 / 换目录）也返回 409 并提示重新下载。

### 失败也记下回退点

安装阶段（`npm install` 失败，或 `git merge --ff-only` 失败）失败时，把更新**前**取好的
回退点正式写入状态并标记 `failed: true`。这样：

- 设置页立刻出现「回退到更新前」；
- `POST /rollback` 直接可用，不需要先"成功更新一次"。

### 失败阶段可见

每个失败分支都带上 `phase`（`resolve` / `download` / `verify` / `install` / `fetch` / `merge`），
`lastUpdate` 因此能给出 `canRetry` / `canRollback` / `attempt` / `needsFreshDownload`。
判定规则很直接：**只有安装阶段失败才提供"重试安装"与"回退"** —— 下载失败有断点续传那条路，
抓取失败则是"还没开始"。

### 重试前重新校验

`installStagedPackage` 在每次安装前重算一次哈希。理由有二：

1. 包在这期间可能被改动过，重试必须仍然装上"当初校验通过的那份字节"；
2. 如果本地包已经不可信，就删掉它并**如实说"需要重新下载"**（`needsFreshDownload`），
   而不是继续承诺"直接重试"。

### 客户端

安装失败时多出一行说明（第几次尝试 + 失败原因 + 包是否还在）与两个按钮：
「**重试安装**」「**回退到更新前**」。

## 三、关键决策与取舍

| 决策 | 理由 | 代价 |
|---|---|---|
| 拆成"准备 / 安装"两步 | 安装失败时前一步的成果仍然有效，重试不必重下 | 多一份 `stagedPackage` 状态与"位置是否变了"的匹配检查 |
| 重试前重新校验 | 否则"重试"装的可能不是当初校验过的字节 | 每次安装多一次哈希（几十 MB 约百毫秒） |
| 本地包失效时不再承诺重试 | 装一个来路不明的包比"多下一次"更糟 | 用户需要重新下载（但会明确告知） |
| 失败时也写回退点 | "装到一半失败"正是最需要退路的时刻 | 状态里多一个 `failed` 标记，回退语义要写清楚 |
| 只有安装阶段失败才给重试/回退 | 下载失败属于"没准备好"（续传），抓取失败属于"还没开始" | 每个失败分支都要打 `phase`，漏一个就退化成"没有出路" |
| 重试要校验安装位置 | 拿旧包往新目录里装是错的 | 多一个 409 分支与提示 |

## 四、验证记录

### 自动化测试（`npm test`，9 个脚本全部通过）

| 脚本 | 本版新增的覆盖 |
|---|---|
| `local-check.mjs` | **10 条**路由；第 9 节：没有失败记录时 `/update/retry` 返回 409、非本机来源 403、GET 405；快照带出 `stagedPackage` / `lastUpdate` |
| `e2e-local-repo.mjs` | 第 11 节（**真实 git**）：造出"本地分叉 + 上游前进"，`/update` 以 `phase: 'merge'` 失败且**没有动 HEAD** → 状态标记 `canRetry` / `canRollback` / `attempt: 1` 且 `rollback.failed === true` → `/update/retry` **复用 FETCH_HEAD**（日志可证）仍然失败且 `attempt` 累加到 2 → `/rollback` 成功回到失败前那一刻 |
| `client-render.mjs` | 第 13 节：安装失败态的说明文案与两个按钮存在，「重试安装」确实打到 `/update/retry`；`needsFreshDownload` 时如实说明需要重新下载 |

其余脚本（`schedule` / `semver` / `proxy-parse` / `npm-layout` / `download` / `verify`）维持前一版覆盖。

### 尚未在真机验证的部分（如实记录）

- 与 v0.2.5 相同：本机 dsh 是**源码形态**，所以 npx / npm 形态的"暂存包 → 重试安装"路径
  只在 `e2e` 的源码形态分支与 `client-render` 的渲染层被覆盖，没有在真实 registry 上端到端跑过。
- 新增的 `POST /update/retry` 需要**重启 `dsh web`** 才注册得上，本次未重启。

## 五、已知限制

- **重试只针对安装阶段**。下载失败请用「立即更新」（走断点续传）；抓取失败同理。
- **源码形态的重试依赖 `FETCH_HEAD` 还在**。git 会保留它，但若被外部清理，
  插件会明确提示"没有可复用的抓取结果，请用「立即更新」重新抓取"，而不是默默再抓一次。
- **插件不修复安装失败的根因**。权限不足、磁盘满、依赖树冲突这些仍然要人来处理 ——
  这一版做的是让失败**可重试、可回退、可解释**，而不是让它不发生。
- 更新后仍需重新构建并重启（源码形态）；宿主端改动一律需要重启 `dsh web`。

## 六、开发过程时间线

1. **先定失败分类**（`phase`）—— 决定 UI 给出路的依据是"失败在哪一步"，所以先把每个失败
   分支标上阶段：`resolve` / `download` / `verify` / `install`，源码侧是 `fetch` / `merge`。
2. **拆 `applyPackageUpdate`**：前半段留作"准备安装包"，后半段抽成 `installStagedPackage`。
   安装失败时把 `staged` 一起返回 —— 这是"只重试安装"能成立的全部前提。
3. **源码形态的重试路径**：`applyGitUpdate` 增加 `retry` 分支，用
   `git rev-parse --verify --quiet FETCH_HEAD` 判断上次抓取是否还在，在就只重做合并。
4. **把 `/update` 的流程抽成 `runUpdateTask`**，让 `/update` 与 `/update/retry` 共用同一套
   落状态逻辑 —— 否则"失败也要记回退点"这件事会被复制成两处、迟早写歪。
5. **失败也记回退点**：安装阶段失败时写入 `rollback`（带 `failed: true`），
   于是 `/rollback` 在那之后立刻可用。
6. **客户端**：失败说明行 + 「重试安装」「回退到更新前」两个按钮。
7. **测试**：`local-check` 补路由与 409/403/405；`client-render` 补失败态与请求落点；
   `e2e` 新增第 11 节 —— 用真实 git 造出分叉，把"失败 → 重试 → 回退"整条链路跑一遍
   （其中"重试不重新抓取"是用日志断言的）。
8. **两处断言核对**：路由数 9 → 10（`local-check` 与 `e2e` 各一处，这是本仓库的老约定）。
