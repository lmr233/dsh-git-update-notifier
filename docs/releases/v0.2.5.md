## 一、这一版要解决的问题

v0.2.0 让插件认得清三种部署形态，也能退回任意版本。但"更新"这个动作本身还是**一次性的**：

```js
const result = await runNpm(['install', `@deepseek-ai/dsh@${target}`], cwd, proxy)
```

这行代码有两个盲区。

**其一，中断即清零。** dsh 的发布包是几十 MB 量级，弱网下可能下到 80% 断掉。原实现把下载
整个交给了 npm：进程一结束、连接一断，进度就没了，用户只能看着它从头再来一遍。更糟的是
**看不出卡在哪** —— `npm install` 失败时给的是它自己的报错，分不清是"网断了""包坏了"
还是"装不上"。

**其二，装的东西没有独立验证。** npm 自己会校验 tarball 的 integrity，但那是在它内部、
用它的凭据去校验它自己下载的字节。插件作为"替用户做决定的人"，在把字节交给 npm 之前
拿不到任何判断依据 —— 它只是把版本号转述给 npm，然后相信结果。

所以 v0.2.5 把更新的前半段**收回自己手里**：

```
拿 dist 元数据 → 自己下载（可断点续传）→ 自己校验 → 装这份校验过的本地包
```

要让"校验"有意义，被校验的字节就必须**就是**被安装的字节 —— 这是本版所有设计取舍的源头。

## 二、交付内容

### 下载器 `lib/download.js`（新增）

- **Range 断点续传**：数据写 `<file>.part`，进度记 `<file>.part.json`（url / etag /
  total / downloaded）。下次带 `Range: bytes=<已下载>-` 续传；服务端回 206 就接着写，
  回 200（不支持续传）就截断重下。
- **跨进程**：进度按 512 KB 粒度落盘，所以 dsh 重启后依然从断点继续 —— 不只是"同一次
  会话内重试"。
- **可取消**：接受 `AbortSignal`；取消只保留 `.part`，不删。
- **失效判断**：断点只在"同一 URL 且 `.part` 大小与元数据一致"时才认；
  服务端回的 `Content-Range` 起点对不上就丢掉不可信的断点并要求从零重来（`retryFromScratch`）；
  `416` 且长度正好吻合时按"其实已经下完"处理。
- **卡死判定**：60s 没有新数据就结束本次下载并保留断点（连接半死时不会永远挂着）。
- 网络策略与 registry 查询一致：**先直连、失败再走 HTTP CONNECT 代理**。
- 另提供 `probeRemoteSize()`（`bytes=0-0` 探测大小与是否支持续传）与 `clearPartial()`。

### 校验 `lib/verify.js`（新增）

三层校验，各自对应一种失效方式：

| 层 | 依据 | 能发现 |
|---|---|---|
| 内容寻址 | `dist.integrity`（通常 sha512，SRI 形式） | 传输损坏、中途篡改 |
| 经典校验和 | `dist.shasum`（sha1） | registry 只给 shasum 时的兜底 |
| 包身份 | tarball 内 `package/package.json` 的 name + version | "校验和正确但装错了包" |

- 前两层**至少要有其一**；两层都缺就拒绝安装 —— 没有凭据的"通过"是假的。
- tar 读取是流式状态机（`readTarEntry`）：逐块前进、跳过非目标条目，不把整个 tarball
  读进内存，也不依赖外部 `tar` 命令。

### 宿主端接入 `lib/index.js`

- **npx / npm 形态**的更新改为：取单版本 manifest（`fetchVersionManifest`）→ 下载
  （续传）→ 校验 → `npm install <校验过的本地 tgz>`。
  项目形态加 `--no-save --no-package-lock`（不改用户的 `package.json` / lock）；
  npx 缓存把依赖版本写回目标版本（否则下次 `npx @deepseek-ai/dsh web` 会另开缓存目录）。
- **源码形态**的 `git pull` 拆成 `git fetch`（原来就有的退避重试与代理回退）+ 本地
  `merge --ff-only`。中断点只可能落在 fetch，而 git 会把已下载的对象留在 `.git/objects`，
  所以"重试即续传"是 git 自身的语义 —— 插件负责的是把它**单独拆出来并如实呈现**。
- **新增状态字段**：`progress`（在途阶段/字节数，进程内）、`pendingDownload`（磁盘断点，
  跨进程）、`lastUpdate`（上次更新的包校验结论），随 `status.json` 一起带出。
- **新增两条路由**（共 9 条）：`GET /progress.json`、`POST /download/cancel`
  （默认保留断点，`?discard=1` 丢弃）。
- npm 参数白名单放行 `\` 与 `:`（本地 tarball 的 Windows 路径需要），仍拒绝空格与 shell
  元字符；路径不安全时**退回按版本号安装**，并在结果里如实标注"本次未做校验"。

### 客户端 `lib/client.js`

- 更新进行中轮询 `/progress.json`（仅此时轮询），显示阶段、`已下载 / 总大小`与百分比，
  并标注"从断点续传"。
- 有磁盘断点时提示"上次下载中断，已保留 X / Y（版本 Z），再点一次会从断点继续"。
- 展示上次更新的包校验结论（逐项 ✓ / ✗，含具体值）。
- 提供「中断下载」与「中断并丢弃断点」。

### 工程

- `test/` 增至 **9 个可独立运行的脚本**，全部离线、进 CI。
- 新增 `test/download.mjs`（本地 http server 扮演 tarball 端点）与 `test/verify.mjs`
  （手写最小 UStar tar 构造坏包）。

## 三、关键决策与取舍

| 决策 | 理由 | 代价 |
|---|---|---|
| 自己下载，而不是让 npm 去下 | 只有拿着字节流才能做续传与**装前**校验 | 多一层缓存目录与失效判断 |
| 安装改为装本地 tarball | 校验过的字节必须就是被安装的字节，否则"校验"是装饰 | npm 会记成 `file:` 依赖，需要额外处理（`--no-save` / 写回 npx 清单） |
| 断点存 `.part` + `.part.json`，不写状态文件 | 大文件进度按块写，不该反复重写用户的 dsh 状态文件 | 需要处理"URL 变了/区间对不上/文件被删"等失效情形 |
| 服务端回 200 就截断重下 | 不支持 Range 的镜像上"续传"是假的，宁可重来 | 弱网 + 老镜像时可能重复下载 |
| 校验不过就删包重下 | 断点接在一个坏包上没有意义 | 弱网 + 坏源时会反复重下（但会明确告知） |
| 两层凭据都缺就拒绝安装 | 没有凭据的"校验通过"是假的 | 个别镜像会导致无法更新（改为给出明确原因） |
| 源码形态拆 `fetch` + `merge` | 中断点只在 fetch；拆开后能看清卡在哪、也能单独重试 | 多一次 git 调用 |
| 成功安装后仍保留 tarball | 安装环节失败时重试不必重下；也让"校验过的那份"可复查 | 占用磁盘（卸载说明里已注明清理路径） |

### 尚未在真机验证的部分（如实记录）

- 本机 dsh 是**源码形态**，所以"下载 + 校验 + 装本地 tarball"这条路径**没有在真机上跑过**
  —— 它只对 npx / npm 形态生效。该路径由 `download.mjs`（续传的每条分支）与 `verify.mjs`
  （每种坏包）在本地 http server / 手工构造的 tarball 上覆盖，但**没有**在真实 registry
  的字节流上端到端验证过。
- 进度与断点路由需要**重启 `dsh web`** 才注册得上（宿主端改动的固有约束），本次未重启。

## 五、已知限制

- **断点只对同一版本、同一 URL 有效**。目标版本变了就重新下载 —— 拼接不同版本的字节没有意义。
- **校验依赖 registry 提供凭据**。官方 `dist` 一定带 `integrity` 或 `shasum`；都不带的镜像
  会被拒绝安装（而不是"假装通过"）。
- **源码形态的"续传"由 git 完成**，插件做的是把 fetch 单独拆出来、可重试、可观察，而不是
  自己实现一套对象级别的续传。
- **更新后仍需重新构建并重启**才生效（源码形态）；宿主端改动一律需要重启 `dsh web`。
- **代理探测只覆盖 Windows 注册表与环境变量**；macOS 的 `scutil --proxy` 尚未覆盖。

## 六、开发过程时间线

本轮开发在一次会话内完成，按落地的顺序：

1. **先写下载器**（`lib/download.js`）—— 它是"续传"的全部载体。设计上刻意把断点信息放在
   与文件同名的 `.part.json` 里，使"续传起点"只依赖版本号一个输入，重启后也找得回来。
2. **再写校验**（`lib/verify.js`）—— 顺序不能反：先有"被校验的字节"，才谈得上校验。
   为此手写了一个流式 tar 读取器，避免为读一个 `package.json` 把整包读进内存，
   也避免依赖外部 `tar` 命令（CI 上要跨平台）。
3. **registry 取单版本 manifest** —— 下载地址（`dist.tarball`）与校验凭据（`integrity` /
   `shasum`）都在这份文档里，原来只取 `dist-tags` 是不够的。
4. **改安装路径** —— 从 `npm install @deepseek-ai/dsh@<版本>` 变成装本地 tarball。
   顺带发现 `runNpm` 的白名单不含 `\`，Windows 上的本地路径会因此退回不带 shell 的
   spawn 并报 EINVAL；放行 `\` 与 `:` 后仍保留"路径不安全就退回按版本号安装"的兜底。
5. **源码形态拆分** —— `git pull` → `git fetch` + `merge --ff-only`，让中断点可观察、可重试。
6. **进度与中断路由** —— 更新是同步阻塞的，所以用 `GET /progress.json` 让 UI 轮询；
   `POST /download/cancel` 走 `AbortController`，默认保断点。
7. **客户端** —— 进度行、断点提示、校验结论、两个中断按钮；只有更新进行中才轮询。
8. **测试** —— 先写 `download.mjs`（本地 http server 可以按指令掐断、忽略 Range、谎报区间、
   慢慢发），再写 `verify.mjs`（手写 UStar tar 造坏包），最后补 `client-render.mjs`
   与两处路由数断言（7 → 9）。
9. **两个由测试暴露的真实缺陷**：服务端忽略 Range 时 `resumedFrom` 会把"磁盘断点位置"
   误报成"续传了多少"；对端直接掐断连接时不一定触发 `error`，改为同时依据 `complete` 判定。
